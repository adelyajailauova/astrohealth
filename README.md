# GaryshCare: мониторинг здоровья астронавтов

Прототип для хакатона «Create Health Monitoring Software for Astronauts on Space Missions».

Как это работает:
1. Носимые датчики (умная рубашка в стиле CSA Bio-Monitor) снимают показатели.
2. **Бортовой узел** оценивает их в реальном времени, показывает астронавту статус и подсказку, что делать.
3. Данные **автоматически** уходят врачам на Землю по каналу с реальной задержкой связи и приоритетами (store-and-forward).
4. Блок **wellbeing** даёт дыхательные практики и медитацию, когда чек-ин показывает стресс или недосып.

> Датчиков в прототипе нет, показатели **симулируются**. Все пороги и рекомендации взяты из официальных источников (NASA, NIH). Если правило придумали мы сами, оно помечено как «app rule». Полный список с цитатами — на вкладке **Evidence** и в [RESEARCH.md](RESEARCH.md).

## Почему это нужно (из источников)
- **NASA-STD-3001 Vol.1, V1 3004** требует от миссии: мониторинг и тренды жизненных показателей, ЭКГ, приватную передачу медданных на Землю, автономную медпомощь и доказательные поведенческие протоколы на электронных устройствах.
- NASA HRP: среди сердечно-сосудистых рисков названы аритмии и низкое давление с обмороками при смене гравитации. Задержка связи с Марсом — до 20 минут в одну сторону.
- CSA Bio-Monitor (на МКС с 2018 года) уже измеряет ЭКГ, давление, SpO₂, дыхание и температуру. Мы добавляем к этому оценку на борту, подсказки и сортировку отчётов для врачей.

## Стек
- **backend/** — Python 3 + FastAPI + WebSocket: симулятор датчиков, движок оценки, канал связи.
- **frontend/** — React + TypeScript + Vite + Recharts: экраны экипажа, Mission Control, wellbeing, Evidence.

## Запуск
Для команды: как клонировать проект, работать в ветках и открывать Pull Request — в [CONTRIBUTING.md](CONTRIBUTING.md).

```bash
python3 -m venv .venv && .venv/bin/pip install -r backend/requirements.txt
```
```bash
.venv/bin/uvicorn app.main:app --app-dir backend --port 8000
```
```bash
cd frontend && npm install && npm run dev
```
Откройте http://localhost:5173.

## Демо-аккаунты
Вход по роли. Астронавт видит только свои данные, медперсонал видит весь экипаж и Mission Control. Разделение проверяется на сервере, а не только в интерфейсе.

| Роль | Аккаунт | PIN |
|---|---|---|
| Астронавт | `sato` (Cmdr. A. Sato) | 1111 |
| Астронавт | `moreau` (Dr. L. Moreau), включено отслеживание цикла (демо) | 2222 |
| Астронавт | `okafor` (Eng. R. Okafor) | 3333 |
| Медперсонал | `surgeon` (Flight Surgeon) | 9000 |

Это демо-вход для прототипа: PIN-коды фиксированные, сессии хранятся в памяти и сбрасываются при перезапуске бэкенда. В реальной системе вход шёл бы через систему идентификации агентства.

## Структура
| Файл | Что внутри |
|---|---|
| `backend/app/sources.py` | Реестр источников с цитатами (единый источник правды) |
| `backend/app/assess.py` | Правила оценки: пороги → статус (normal/watch/alert/critical) + совет + источники |
| `backend/app/simulator.py` | Симуляция датчиков и демо-сценарии |
| `backend/app/comms.py` | Канал «борт ↔ Земля»: задержка МКС/Луна/Марс, приоритеты, ограничение полосы, потеря связи |
| `backend/app/main.py` | API, WebSocket, главный цикл, проверка прав доступа |
| `backend/app/auth.py` | Демо-вход: роли «астронавт» и «медперсонал» |
| `frontend/src/pages/*` | Crew console, Check-in & wellbeing, Mission Control, Evidence |

## Сценарий демо (≈3 минуты)
1. **Crew console**: фигура человека с цветными зонами. Клик по сердцу показывает показатели, «зачем мерить в космосе», совет и ссылку на источник.
2. В демо-панели нажать **Irregular heart rhythm**. Сердце становится оранжевым, появляется баннер с инструкцией, ЭКГ становится неровной.
3. **Mission Control**: выбрать **Mars**. Отчёт приходит через 20 с (20 минут реальной задержки, сжатые ×60). Показать, что бортовая подсказка появилась сразу, без ожидания Земли.
4. Нажать **Simulate loss of signal**, у второго астронавта включить **Falling SpO2**. Отчёты копятся в очереди. После восстановления связи первым приходит critical.
5. Отправить сообщение экипажу (uplink) и показать, что оно приходит с задержкой.
6. **Check-in**: настроение 2, стресс 4, сон 5.5 ч. Приложение рекомендует дыхательную практику. Запустить её и отметить настроение «до/после».
7. **Evidence**: каждый порог со ссылкой на источник. Видно, где правило взято из источника, а где это наше решение.

## Ограничения (честно для жюри)
- Данные датчиков и ЭКГ синтетические, а детекция аритмии — это демо-флаг, а не медицинский алгоритм.
- Пороги — общие нормы для взрослых (NIH). В реальной миссии flight surgeon настраивает их под базовые показатели конкретного астронавта до полёта.
- Это не медицинское изделие.
